# 标准任务 · 库存管理模块（编码 · 自行设计接口）

## 任务描述（对所有组完全一致）
> 为一个小型电商仓库场景设计并实现一个**库存管理 Python 模块**（可 `import` 的模块 + 可运行 demo）。
> **接口（类名、方法名、函数签名、数据结构、错误机制）由你自行设计**——任务**不预定义任何接口**；你须先设计接口，再按你的接口实现，并跑通全部验收场景。只允许使用 Python 标准库。

## 需求约束（必须满足，WHAT 已指定；HOW 由你决定）
- **R1 SKU**：库存按 SKU 管理；SKU 为字符串标识（如 `"SKU-A"`），支持多个 SKU 并存且互不影响。
- **R2 入库**：可增加某 SKU 库存；数量必须为正整数，数量 ≤ 0 必须报错（且可区分于其他错误）。
- **R3 出库**：可扣减某 SKU 库存；库存不足时**必须失败**（任何情况下不得出现负库存），且「库存不足」与「SKU 不存在」必须是两种**可区分**的错误/结果。
- **R4 预留**：可预留库存（预占可用量）；预留后「可用库存」= 总库存 − 已预留；预留量不得超过可用库存（**防超卖**）；可释放已预留量，释放量不得超过已预留量。
- **R5 阈值与低库存**：可为 SKU 设置最低库存阈值；可查询当前**低于**阈值的 SKU 列表。
- **R6 并发安全**：模块必须**线程安全**——多线程并发入库/出库/预留/释放不得丢更新、不得超卖、不得出现负库存。
- **R7 零依赖**：只允许 Python 标准库，不得引入任何第三方包。
- **R8 可查询**：可查询某 SKU 的总库存与可用库存；SKU 不存在时结果须可区分。

## 验收场景（S1~S7，用你设计的接口全部跑通）
- **S1 入库**：`SKU-A` 入库 100 件 → 总库存 100、可用库存 100。
- **S2 出库与不足**：出库 30 → 总/可用 70；再出库 80 → **失败**，库存仍为 70。
- **S3 预留与防超卖**：预留 50 → 可用 20；再预留 30 → 失败（可用仍 20）；再出库 30 → 失败（不发生超卖/负库存）。
- **S4 释放**：释放 50 → 可用恢复 70。
- **S5 阈值告警**：`SKU-A` 阈值设为 80 → 低库存列表含 `SKU-A`（70 < 80）；阈值改 60 → 不再含。
- **S6 并发**：8 线程各入库 10 件 → 总库存**精确** +80；100 件库存下 10 线程各出库 30 → **恰 3 次成功**、不超卖；100 件库存下 10 线程各预留 30 → **恰 3 次成功**、可用不为负。
- **S7 可区分错误**：查询/操作不存在的 SKU，与「库存不足」「参数非法」返回**可区分**的结果或异常。
