# 运营手册 v0.2

> 依据 EXP-001~005 五轮实验证据沉淀。变更：v0.1 → v0.2。

## R1 · 任务分级路由
| 任务特征 | 模式 | 角色数 |
|---|---|---|
| 低复杂度 / 确定性 | 单人直出 | 1 |
| 中复杂度 | 默认单人；高价值才协作 | 3 |
| 高复杂度 / 开放 / 跨学科 | 多角色协作 | 3（甜点） |

## R1a · 多稿处理
- 默认**独立生成 → 择优**（性价比最高）。
- **融合**仅用于需合并多方实质要素时（如全维度 OKR）。
- 更多角色 = 补维度覆盖，不补质量上限。

## R2 · 实验先行
- 重大决策先小样本验证再规模化；不建无用基建。
- 每实验必存协议 + 报告，可复现可追溯。

## R3 · 诚实汇报
- 结论标注证据强度（n、任务类型、评测方式）。
- "无显著差异"也是有效结论。

## R4 · 独立评审
- 正式输出（定位/愿景/OKR）须经独立评审，避免自评偏差。
- 采纳前声明评审者与撰写者关系。

## R5 · 知识沉淀
- 每轮决策落地为正式文档（statement / OKR / manual）。
- 实验证据链与决策一一对应，可回溯。


## R6 · 管理层角色边界（2026-08-11 创始人指令）
- **CEO 不执行具体事务**：不亲自撰写文档正文/代码/报告/公告等产出物。
- **CEO 职责**：任务定义、授权分派、资源协调、验收裁决、制度维护、向创始人汇报。
- **事务授权制**：具体工作按《任务授权书》（目标/验收标准/授权对象/自主权边界/交付物/评审方式）分派给部门或员工。
- **环境例外**：涉及运行环境/凭据/账号的安全操作（如 GitHub 发布需 gh 令牌、网络工具部署），由 CEO 代为执行；但产出与结果仍按授权与验收流程闭环，CEO 不自评自己的代执行成果。
- **双向评审**：正式产出须经独立评审（R4）；员工也可评审 CEO 的制度与决策。

*版本 v0.2 · 2026-08-10 · 证据：EXP-001~005*

## R7 · 两级授权链（2026-08-11）
- **CEO 不对执行人直接分派**；只对部门负责人（管理层）下发任务授权。
- **部门负责人职责**：任务拆解 → 调度执行 → 督导进度 → 质量验收 → 向 CEO 汇报部门成果。
- **执行人**：向所属部门负责人汇报，不对 CEO 直接汇报（例行汇报除外）。
- **授权链**：CEO → 部门负责人 → 执行人；**汇报反向**：执行人 → 负责人 → CEO。
- **部门归属**（7 岗）：
  | 部门 | 负责人 | 执行人 |
  |---|---|---|
  | 研究院 | 研究员 | 数据科学家 |
  | 工程部 | CTO | （可调度工程任务） |
  | 产品部 | PM | 市场官 |
  | 运营部 | COO | 合规官 |
- **规模例外**：部门负责人可亲自执行本部门任务（虚拟组织规模小），但必须保留"拆解-验收-汇报"的管理闭环。
- **技术约束**：spawn 执行代理需运行环境协调，由 CEO 代为创建；执行结果仍按"执行人→负责人→CEO"汇报验收。

## R6a · 信息检索与数据收集亦属执行事务（2026-08-11 追加）
- **CEO 不亲自搜索/检索/收集数据**（联网搜索、页面抓取、数据整理均为执行工作）。
- 执行团队（研究员/数据科学家等）**自行检索与核验数据**；CEO 只做数据质量的验收与任务定义。
- CEO 例外收窄为：账号/凭据/运行环境的安全操作（如 GitHub 发布需令牌、文件系统与 git 环境维护）。
- 若执行团队确实无法访问某数据源（技术受限），由执行团队**上报** CEO，CEO 再协调资源——而非 CEO 默认代劳。
- 经验来源：TK-011 中 CEO 亲自联网取数被创始人指出，违反 R6；执行团队本具备联网能力。
