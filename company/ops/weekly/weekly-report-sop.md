# 周报 SOP · 运营周报机制

> 版本：v1.0 · 2026-08-11 · 起草：COO（运营部）· 验收：CEO @ 周会
> 目标：让 Runbook 的"每周：周会 + 周报"真正落地——一份周报同时承载 OKR 进度、待办核查、产出证据、风险上报与下周计划，形成可持续运营节奏。

## 1. 谁写（责任矩阵）
| 环节 | 角色 | 职责 |
|---|---|---|
| 主笔 | COO（运营部负责人） | 汇总各部门数据，撰写周报初稿（规模例外下 COO 亲自执行，保留拆解-验收-汇报闭环，见 R7） |
| 数据提供 | 各部门负责人（研究院/工程部/产品部/运营部） | 提交本部门产出、KR 进展、风险与阻塞（执行人 → 负责人） |
| 协作 | 合规官 | COO 可授权其收集风险清单、核查待办状态与文档纪律 |
| 评审/验收 | CEO | 周会上对照验收标准逐节验收，通过后归档为正式周报 |

## 2. 写什么（内容清单，对应模板 weekly-report-template.md）
1. **OKR 进度**：每个 KR 的周初值 → 周末值 → 变化；本季待办逐条核查
2. **待办核查**：上周结转逐条结论（完成/延后/取消/风险），不留悬空
3. **本周产出**：带证据（Run 编号、文件路径、Issue/Release 链接）
4. **风险与阻塞**：影响 + 应对 + 上报对象
5. **下周计划**：≤3 件事，标负责人/截止/路由模式（R1 单人 or 协作）
6. **决议与建议**：给 CEO/创始人的制度或资源建议

## 3. 何时写（时间线）
| 时间 | 动作 |
|---|---|
| 每周五 11:00 前 | 各部门负责人向 COO 提交本部门周数据 |
| 每周五 16:00 前 | COO 完成周报初稿，标记 🔄 草稿 |
| 周会（周五或次周一） | CEO 逐节评审 → 修订 → 标记 ✅ 已归档 |
| 周会后 30 分钟内 | 同步 okr-tracker.md（KR 状态/当前值）、待办结转进下周 |

- 周五为节假日 → 提前到最后一个工作日
- 应急触发：创始人/CEO 说"出周报"或"汇报进度" → COO 基于最新运行日志 + okr-tracker 现场出报告

## 4. 存哪里（存储与命名）
| 内容 | 位置 | 命名 |
|---|---|---|
| 周报 | ops/weekly/ | `YYYY-Www-周报.md`（如 2026-W33-周报.md） |
| 周报模板 | ops/weekly/ | `weekly-report-template.md`（复制后填写，不改模板） |
| 周会纪要 | ops/weekly/ | `YYYY-MM-DD-周会.md`（沿用 meeting-sop 命名） |
| OKR 同步 | ops/ | okr-tracker.md（周会后更新） |
| 运行日志 | ops/runs/ | `YYYY-MM-DD-run-NNN.md`（周报的数据源） |

## 5. 与例会如何衔接（meeting-sop）
- **会前**：COO 提交周报初稿 = 周会议程第 1/2 步的输入（上次待办核查 + OKR 扫描）
- **会中**：周会 5 步（核查/扫描/决策/风险/落档）直接以周报为基础；周报中的风险项进"风险上报"环节
- **会后**：周报归档最终版，周会纪要落档（`ops/weekly/YYYY-MM-DD-周会.md`）；两者互链（周报头注明周会日期，纪要对齐周报待办）；待办结转进下周周报

## 6. 质量要求（验收标准，COO 自检 + CEO 验收）
- [ ] 每条产出有证据（Run 编号 / 文件路径 / 链接），无来源不写结论
- [ ] 状态符号统一：✅ 完成　⏳ 待办　🔄 进行中　⚠️ 风险
- [ ] 待办逐条有结论，无"悬空"项
- [ ] OKR 变化与 tracker 口径一致；口径变化需在报告中注明（如"tracker 待同步"）
- [ ] 下周计划 ≤3 件，含负责人/截止/路由模式
- [ ] 概览 3 行先行，全文控制在 2 页内可读

## 7. 版本与迭代
- SOP 迭代：版本 bump，变更记入 CHANGELOG（runbook 文档纪律）
- 每季度月复盘中评审一次周报机制有效性；试运行 2 周后做首次复盘
