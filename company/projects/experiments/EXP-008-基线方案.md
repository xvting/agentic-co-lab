# EXP-008 基线方案 · 日志分析器（首跑基线）

- **实验编号**：EXP-008（首跑基线）
- **日期**：2026-08-11
- **主持/督导**：研究院负责人（主代理）
- **授权链**：CEO → 研究院负责人（R7 两级授权）
- **任务来源**：`benchmark/tasks/task-coding-log-analyzer.md` + `benchmark/tasks/test_suite_log_analyzer.py`（30 断言）
- **目标**：为首个标准编码·数据处理任务建立第一批真实基线数据，回填 README「已知基线」。

## 1. 研究问题与设计意图

日志分析器是**中等复杂度、边界密集**的编码任务（30 断言：非法行、token 顺序、非负整数、空输入、tie-break 等），与 EXP-002 的简单确定性任务（括号匹配 15/15、协作零增益）形成对照。

**研究问题**：在边界密集型编码任务上，3 角色独立生成是否相对单人直出带来鲁棒性增益（通过率/质量分布）？首跑只回答「基线长什么样」，不回答统计显著性。

**组设计（首跑）**：3 个独立执行代理（3 个角色视角）各写 1 份解 → 客观套件评测 → 择优稿 → 建立单人/多稿基线。本跑不做融合（融合留待后续 EXP 对照），保持口径干净。

## 2. 评测流程

1. **准备**：确认套件 30 断言可运行（已完成自检：参考实现 RESULT 30/30，参考实现不计入基线）。
2. **生成**：3 个执行代理按第 4 节要求独立产出 `log_analyzer_<role>.py`，落盘 `company/projects/experiments/EXP-008-runs/`。
3. **客观评测**：逐份执行 `python benchmark/tasks/test_suite_log_analyzer.py <解文件>`，记录 `RESULT n/30` 原文与失败断言明细（`FAIL name :: reason`）。
4. **主观质量评分**：按 `tasks/rubric.md` 编码类三维（可读性/健壮性/效率，各 1-5，总分 15），匿名编号、评审与撰写分离。
5. **择优**：按第 3 节规则确定择优稿，记录理由。
6. **基线落档**：记录单人/多稿口径与成本，回填 README「已知基线」。

## 3. 基线指标定义

| 指标 | 定义 | 记录要求 |
|---|---|---|
| 客观通过率 | `passed/30`（RESULT 分子/30） | 每份记录 `RESULT n/30` + FAIL 明细 |
| 质量分布 | rubric 编码类 3 维 × 1-5（总分 15） | 每份记录 3 维分 + 总分 |
| 择优稿 | 客观通过率高者优先 → 主观总分 → 健壮性 → 效率 | 记录择优稿标识 + 理由 |
| 单人（单稿）基线 | 3 份独立稿通过率分布（n=3） | min / 中位 / 逐份 |
| 多稿（择优）基线 | 择优稿通过率 + 质量分（n=1 择优） | 择优稿完整记录 |
| 过程成本 | 代理数 × 轮次 | 记录实际值 |
| 诚实标注 | n=3、单轮直出、无融合、探索性 | 结论中显式声明 |

## 4. 执行要求（3 个解）

**执行代理**：3 个互不沟通的独立执行代理，各取一个角色视角（研究员/CTO/PM），只基于任务文档独立完成。

### 4.1 交付与命名
- 文件：`EXP-008-runs/log_analyzer_researcher.py`、`log_analyzer_cto.py`、`log_analyzer_pm.py`（推荐 agent 名：Turing / Hopper / Babbage）。
- **直接输出完整可运行的 Python 代码**（模块级 5 个函数，无 `main` 依赖），**不要解释文字**；如确需附注，用代码内注释。

### 4.2 接口约束（必须实现，签名与任务文档完全一致）
| 函数 | 签名 |
|---|---|
| parse_logs | `parse_logs(text: str) -> list[dict]` |
| count_by_level | `count_by_level(entries: list[dict]) -> dict[str, int]` |
| error_rate_by_service | `error_rate_by_service(entries: list[dict]) -> dict[str, float]` |
| avg_ms_by_endpoint | `avg_ms_by_endpoint(entries: list[dict]) -> dict[str, float]` |
| top_slowest | `top_slowest(entries: list[dict], top_n: int) -> list[str]` |

### 4.3 行为约束（严格按任务文档）
- 仅允许 Python 标准库。
- **解析**：每行 6 个空白分隔 token；前两个为 ts/level（任意字符串原样保留）；后四个必须按 `svc= ep= status= ms=` 顺序；`status`/`ms` 仅为 0-9 非负十进制整数（负数、缺序、多余 token 等一律跳过）；非法行在 `parse_logs` 中跳过。
- **统计**：`count_by_level` 按 level 计数；`error_rate_by_service` 中 `status >= 500` 计错误，rate = 错误数/该服务条目数；`avg_ms_by_endpoint` 为 float 均值。
- **排序**：`top_slowest` 按 endpoint 平均 ms 降序，平均相同按名称字典序升序，最多 `top_n` 个；`top_n <= 0` 或空输入返回 `[]`。
- **稳健**：所有函数对空输入返回 `{}` 或 `[]`，不抛异常。

### 4.4 独立性
- 互不沟通、不读取其他代理草稿、不得调用他人代码；基于任务文档独立完成。
- 可（可选）自跑一次套件自检，但回报时必须附**原始** `RESULT n/30` 与失败明细。

### 4.5 回报格式（每份）
`角色 | RESULT n/30 | 失败断言明细（如有）`

## 7. 已知局限（诚实声明）

- **n=3**：样本极小，仅作探索性参考线，不具备统计意义；不据此下「协作有无增益」结论。
- 首跑为**单轮直出、无融合**；择优稿≠融合稿，与 EXP-002「整合终版」口径不同，跨实验比较需注明。
- 主观分为本次评审单次打分；非多评审取均值，不视为稳定质量分。
- 首跑基线仅代表当前代理栈在单轮下的水平，后续随模型/提示词/协议更新需重跑。
