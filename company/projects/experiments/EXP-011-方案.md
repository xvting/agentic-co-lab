# EXP-011 方案 · 「自行设计接口」编码任务的协作增益临界点（首跑基线）

- **实验编号**：EXP-011（首跑基线）
- **日期**：2026-08-12
- **主持/督导**：研究院负责人（主代理，本跑唯一评审）
- **授权链**：CEO → 研究院负责人（R7 两级授权，TK-016）
- **任务来源**：`benchmark/tasks/task-inventory-api.md`（编码·自行设计接口）+ `benchmark/tasks/rubric.md`（新增「接口设计类」5 维量表）
- **背景**：矩阵 v6 未解问题①——「自行设计接口」编码任务（无预定义接口，执行者先设计再实现）的协作增益待探索；该类型介于确定性编码（+0%，EXP-002/008）与中等编码（+7%，EXP-003）之间。
- **方法论底线（EXP-010 教训，本方案先于执行固化）**：① 协作臂各稿必须由 **CEO 独立 spawn 的执行代理**生成、互不沟通；② **督导不得代产出稿件作为增益证据**；③ 同源产出不得作为证据（EXP-010 首跑 +13.6% 假象 → 独立复跑 −8.0%）。督导在本跑只做：任务/方案设计、评测装置构建与校准、门槛核验、adapter 撰写、盲评与报告。

## 0. 任务类型定义（自行设计接口·编码）

**自行设计接口·编码** = 任务的**WHAT（业务需求与验收场景）完全指定，但接口（类名/函数签名/数据结构/错误机制）由执行者自行设计**，先设计再实现。与已有类型的区分：

| 类型 | 接口/格式 | 约束来源 | 既有证据 |
|---|---|---|---|
| 确定性编码 | 完全指定（签名+用例） | 接口本身 | +0%（EXP-002） |
| 中等编码 | 指定+设计自由度 | 接口+质量期望 | +7%（EXP-003） |
| 接口明确编码 | 完全指定（5 函数签名） | 接口本身 | +0%（EXP-008） |
| 分析推理 | 固定 5 节结构 | 结构+分析规范 | +0%（EXP-009） |
| 行为规范开放 | 无 | 显式行为规范（检查项清单） | ≈0%（EXP-010 复跑） |
| 开放多维 | 无 | 几乎无 | +19%（EXP-001） |
| **自行设计接口（本实验）** | **无预定义，执行者自定** | **WHAT 指定（需求+验收场景），HOW 自由** | **待测（EXP-011）** |

**关键问题**：与行为规范开放（EXP-010，规范检查项把多稿拉向趋同）不同，本类任务把「接口本身」开放给执行者——接口设计差异（错误语义/数据模型/并发策略/命名）是否创造出可被择优利用的质量方差？这是「协作增益临界点」在编码域的最后一块拼图。

## 1. 研究问题与预注册假设

**研究问题**：在「自行设计接口」编码任务上，3 角色独立多稿的择优增益相对单人直出是多少？在复杂度梯度中处于什么位置？

**预注册假设（先定后测，防事后归因）**：
- **H1 接口设计趋同（→ +0% 档）**：库存模块存在「显而易见」的标准设计（类 Inventory + add/deduct/stock/reserve/release/threshold + 锁），4 稿客观行为测试全过、盲评趋同 → 协作择优增益 ≈ +0%（同 EXP-002/008/009/010）。
- **H2 设计差异 → 择优增益（→ +5%~+15%）**：接口自由度产生真实质量方差（错误语义设计/并发策略/调用体验/扩展性），部分稿明显更优，择优增益落在 +0% 与开放文案 +19% 之间（介于中等编码 +7% 附近）。
- **H3 单人反超（→ <0%）**：如 EXP-010 复跑，角色视角引入偏置、各缺一角，无角色偏置的通用视角最均衡 → 协作择优 < 单人。

**判据（先定）**：
- 客观：4 稿独立行为测试通过率分布（全 33/33 = 客观趋同信号）；
- 主观：盲评总分分布（n=3 协作稿方差）+ 协作择优 − 单人增益所在区间；
- 档位映射：H1 → [−5%, +5%]；H2 → (+5%, +15%]；H3 → < −5%（负向）。

## 2. 组设计与处理路径

- **组设计（首跑）**：4 份独立产出 = 单人组 1 稿（无角色，通用视角）+ 协作组 3 稿（技术负责人·接口与架构 / 业务领域专家·库存域与调用方视角 / 质量与并发工程师·健壮性与测试）。
- **处理路径**：独立生成 → **择优**（直出稿择优，非融合；口径与 EXP-008/009/010 一致，保证跨实验可比）。
- **独立性底线**：4 稿由 CEO 按第 6 节要求**分别 spawn 独立执行代理**生成，互不沟通、不读取他人草稿、只基于任务文档；督导不代产出。

## 3. 评测方式

### 3.1 门槛核验（客观，先于行为测试与盲评；不合规退回重写一轮并记成本）
| 门槛 | 口径 |
|---|---|
| 可导入 | `import inventory` 无异常（stdout/stderr 干净） |
| demo 可跑 | `python demo.py` 退出码 0 |
| 零依赖 | 代码仅用 Python 标准库（扫描 import，人工复核） |
| 交付物齐 | 每稿目录含 `inventory.py` + `demo.py` + `USAGE.md` |
| USAGE 合规 | 含签名/错误语义/最小示例/≤3 句设计决策；正文 ≤500 字（中文，纯汉字口径）；无自夸/自我打分 |

### 3.2 独立行为测试（客观 · adapter 电池，本实验方法贡献）
- **为什么不能直测**：接口由执行者自定 → 无法像 EXP-002/003/008 用固定类名/签名直测。
- **做法**：评测方（督导）按各解 `USAGE.md` 撰写 adapter（**只使用解的公开 API、不改动解代码**），把解 API 归一化为 canonical 操作（`add/deduct/stock/available/reserve/release/set_threshold/low_stock`，错误语义用 `ok/insufficient/unknown/invalid` 状态表达，与解的错误机制解耦），跑统一断言电池 **33 断言**（S1~S7 + 多 SKU 独立 + 3 组并发，并发每轮重复 3 次独立 SKU）。
- **装置**：`EXP-011-runs/_harness/test_suite_inventory_api.py`（已用参考实现校准：33/33；注入错误样例 30/33，确认可检出缺陷；参考实现仅校准，**不计入基线**）。
- **适配难度作为接口可用性信号**：adapter 撰写时间/需否窥探内部/文档缺口 → 记录为「调用可用性」佐证（客观阶段，非盲评）。

### 3.3 主观盲评（rubric「接口设计类」5 维 × 1-5，总分 25）
| 维度 | 1 分锚点 | 5 分锚点 |
|---|---|---|
| 接口清晰度 | 命名混乱、签名歧义、缺类型提示 | 类/方法/参数自解释、命名如自然语言、类型标注完整 |
| 领域建模 | 库存/预留/可用/阈值概念混用、错误语义不可区分 | 概念清晰分离、不变量（非负/不超卖）在正确层强制、错误可区分 |
| 调用可用性 | 新调用方按 USAGE 无法完成场景 | 仅凭 USAGE 即无歧义完成全部验收场景、适配成本低 |
| 健壮性与边界 | 非法输入崩溃、并发丢更新/超卖 | 非法输入全部可区分处理、线程安全、不变量保持 |
| 扩展性与设计 | 单函数大泥球、加场景需重写 | 职责分离、可扩展（批量/多仓/过期等）、无意外 |

### 3.4 盲评规范
- 评审与撰写分离（撰写 = CEO spawn 的执行代理；评分 = 督导，本跑唯一评审）。
- 4 稿脱敏后随机匿名编号 稿A~D（去除 USAGE/代码注释/文件名中的角色标识），映射先行存档 `EXP-011-runs/_blind_r1/_mapping.txt`，评分期间不查看。
- 逐稿 × 逐维打分并附 1-2 句依据；对照 1/5 锚点防分数通胀。

## 4. 基线指标定义

| 指标 | 定义 |
|---|---|
| 门槛通过率 | 5 项门槛逐稿核验（合规率） |
| 客观行为测试 | 每稿 `RESULT n/33` + FAIL 明细 + adapter 适配难度备注 |
| 单人（单稿）基线 | 单人组 1 稿的 5 维分 + 总分（n=1） |
| 协作（择优）基线 | 3 角色稿中按规则择优的 1 稿（n=1 择优）；同时记录 3 稿分布（n=3） |
| 择优规则 | 盲评总分 → 客观断言通过数 → 接口清晰度 → 调用可用性 → 健壮性 |
| 协作增益 | (协作择优分 − 单人分) ÷ 单人分 × 100%（与 EXP-001 口径一致） |
| 过程成本 | 单人=1；协作=3 执行 + 1 督导 = 4 成本单位；性价比=质量分÷成本单位 |
| 诚实标注 | n=1（单人）/ n=3（协作稿）、单轮直出、无融合、单评审、探索性、adapter 由评测方撰写 |

## 5. 标准任务（摘要；完整见 `benchmark/tasks/task-inventory-api.md`）

**任务**：为小型电商仓库场景设计并实现**库存管理 Python 模块**。**接口由执行者自行设计**（类名/方法名/签名/数据结构/错误机制自由），但须满足 8 条需求约束（R1 SKU 管理、R2 入库正整数校验、R3 出库不超卖且「库存不足/未知 SKU」可区分、R4 预留/释放防超卖、R5 阈值与低库存、R6 线程安全、R7 仅标准库、R8 可查询）并跑通 7 个验收场景（S1 入库 / S2 出库与不足 / S3 预留与防超卖 / S4 释放 / S5 阈值告警 / S6 并发精确语义 / S7 可区分错误）。

**交付物**（每稿独立目录）：`inventory.py`（可 import）+ `demo.py`（演示 S1~S7，退出码 0）+ `USAGE.md`（签名/错误语义/最小示例/≤3 句设计决策，正文 ≤500 字中文）。

**背景注入**：所有组同一版本（无额外虚构事实）。

## 8. 已知局限（诚实声明，先于执行写入）

- **n=1（单人）/ n=3（协作稿）**：样本极小，探索性参考线，不具统计意义。
- **adapter 由评测方撰写**：行为测试的 adapter 是督导按解 USAGE 写的（客观阶段非盲），适配难度本身依赖评测方判断；已用「只使用公开 API + 不改解代码 + 固定断言电池」约束，但仍有适配者偏差可能——在报告中声明。
- **单评审**：主观分为督导单次打分，非多评审均值。
- **无融合**：择优稿 = 最高单稿，非融合稿；与 EXP-001/003「整合终版」口径不同，跨实验比较需注明。
- **天花板效应风险**：若多稿客观全 33/33 + 盲评 25/25，量表无法区分更细差异（报告将如实标注）。
- **并发断言的确定性限制**：S6 并发断言重复 3 轮且要求精确语义（恰 3 次成功/精确 +80），但 Python 线程调度下个别无锁实现可能偶然通过，需结合盲评「健壮性」维与代码审查佐证。
- 仅当前代理栈 × 1 轮；模型/提示词/协议更新后需重跑。
