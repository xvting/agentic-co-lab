# 一场"智能体创业"实验：从空目录到开源公司（单日全记录）

> Agentic Co-Lab 案例研究 · 2026-08-10
> 关键词：多智能体组织 / 协作实验 / 证据驱动 / 开源启动包

## TL;DR
用 AI 智能体组建一家"虚拟公司"，从空目录开始，经历**组织搭建 → 六轮对照实验 → 方法论沉淀 → 产品化 → 开源发布**，在一天内完成从 0 到 1 并推向 GitHub。核心产出不是代码，而是一套**经过实验验证的多智能体协作方法论**（Starter Kit）。

## 一、缘起
创始人的问题很开放："能不能形成一个组织去解决问题、达成目标？"
我们把问题具体化：让一群 AI 智能体像一家公司一样运转——有章程、有角色、有会议、有实验、有产品。不做纸面设计，而是**真的运行它**。

## 二、怎么做的
1. **搭骨架**：章程（使命/愿景/价值观/决策机制）+ 组织架构 + 角色卡（身份/培训背景/职责/工作原则）。
2. **开首次会议**：3 名"员工"（研究员/CTO/PM）各提方向提案 → 互相评审 → 投票 → 融合立项。
3. **实验先行**：不先建基建，先用最小成本做对照实验，让方法服从证据。
4. **知识即产品**：把验证过的方法论固化为模板包，对外开源。

## 三、关键数据（六轮实验）
| 实验 | 问题 | 结论 | 证据强度 |
|---|---|---|---|
| EXP-001 | 开放任务：协作 vs 单人 | 协作 +19% | n=1，探索性 |
| EXP-002 | 确定性任务：协作 vs 单人 | 协作 +0% | 15 用例客观评测 |
| EXP-003 | 中等复杂度 | 协作 +7% | 13 断言 + 主观 |
| EXP-004 | 择优 vs 融合 | 择优性价比最高 | n=1，自评偏差已声明 |
| EXP-005 | 团队规模 3/5/7 | 3 角色即饱和 | 嵌套设计，n=1 |
| EXP-006 | Starter Kit 实战 | 全流程可用，R4 有效 | 独立评审抓出真问题 |

**三条核心规律**
1. 协作价值 ∝ 任务开放性 × 复杂度（低 0% / 中 +7% / 高 +19%）
2. 择优上限在 3 角色饱和——扩编补覆盖、不补质量
3. 多稿默认择优；融合仅用于合并实质要素

## 四、关键决策与转折
| 决策 | 理由 | 结果 |
|---|---|---|
| 先实验后基建 | 避免无用投入 | 省下大量开发成本，直取证据 |
| 公司即样本 | 无需外部资源 | 实验零门槛，当天完成 |
| 择优 > 融合 | 融合可能拉低最优稿 | 性价比提升，写入运营手册 |
| 正式输出必经独立评审 | 自评会虚高 | R4 真的抓出了矛盾与缺证据 |
| 知识沉淀为资产 | 一次实验多次复用 | 产出 Starter Kit + 案例 |

## 五、踩过的坑（诚实清单）
1. **自评虚高**：EXP-004 融合版自评 23 分，实为作者偏好，靠独立评审纠偏。
2. **盲目协作**：EXP-002 证明确定性任务协作是 4 倍成本换 0 增益——差点为"协作而协作"。
3. **数字无口径**：早期结论引用缺基线/样本量，评审要求补齐后才可信。
4. **线程资源限制**：EXP-005 第 7 个代理一度因并发上限失败，需分批调度。
5. **发布前置**：git 全局身份是 Gitee，与 GitHub 发布目标错配，需显式设置仓库级身份。

## 六、对读者的启示（可迁移）
1. **组织比模型重要**：角色、流程、评审机制决定了产出质量，而不只是模型能力。
2. **用实验代替争论**：协作有没有用？跑 30 分钟对照实验，比讨论一小时有效。
3. **3 个角色足够起步**：别一上来就 7 个角色，先验证再加人。
4. **择优而非融合**：多数场景下，从多稿里挑最好的，胜过强行合并。
5. **证据要能核验**：对外宣称的每个数字都要能回溯到实验记录。

## 七、局限与展望
- 所有实验 n 小（1~3）、单评审、探索性，不可外推为统计结论。
- 单日完成，样本场景有限（文案/编码/战略三类任务）。
- 展望：外部团队试用反馈 → 模板 v1.2；更大样本实验；多语言文档；真实业务验证。
