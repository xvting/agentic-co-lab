- 授权书：TK-013（研究院负责人授权，两级授权链）。
- 任务：调研 GitHub 上最热门的 AI agent 项目，产出**比较分析与分类总结**，交付至 `docs/research/`（报告 + 过程留痕）。

| 验收标准 | 对应交付物 |
|---|---|

## 二、调研问题

1. 当前 GitHub 上最热门的 AI agent 项目是哪些？用什么度量（star、活跃度、动量）？
2. 它们构成怎样的生态结构？如何分类、分类依据是什么？
3. 在定位/架构/生态/适用场景等关键维度上如何对比？差异背后的原因？
4. 有哪些可复用结论与需要注意的风险？

## 三、样本选取方法（多步骤，防主观偏差）

1. **领域预选**：基于生态知识预选 42 个候选（框架/SDK、多智能体编排、编码与通用 Agent 应用、平台/低代码、协议/基础设施）。
2. **客观检索补漏**：GitHub search API 按 star 排序检索 `topic:ai-agents`（68,427 个结果）、`topic:agent-framework`、`topic:multi-agent`、`topic:mcp` 与关键词 `ai agent` 的 Top30，逐条比对是否遗漏高热度 agent 项目。
3. **第三方榜单交叉**：ai-agent-pulse（2026-08-11 同日更新，19 个框架动量追踪）、Agent-Leaderboard（2026-08-04，5 个板块）。
4. **增补与更正**（检索/榜单发现）：`openclaw/openclaw`（38.6 万★，本生态第一）、`obra/superpowers`、`affaan-m/ECC`、`NousResearch/hermes-agent`、`firecrawl/firecrawl`、`thedotmack/claude-mem`、`google-gemini/gemini-cli`、`anthropics/claude-code`、`bytedance/deer-flow`、`HKUDS/nanobot`、`earendil-works/pi`、`aaif-goose/goose`、`deepset-ai/haystack`、`infiniflow/ragflow`、`a2aproject/A2A`、`agno-agi/agno`、`ComposioHQ/composio`、`karpathy/autoresearch`、`TauricResearch/TradingAgents`；以及 `anomalyco/opencode`（`opencode-ai/opencode` 已归档后的活跃继任）。
5. **排除标准**：非 agent 项目不入主数据集——awesome/榜单类列表、纯 prompt/系统提示词库、纯 RAG 推理服务、面试指南等（在报告「生态邻接」中提及，不参与对比）。
- 最终样本：**60 个项目**（台账总表）。

## 四、数据采集方法

- **数据时点**：快照 `2026-08-11T10:22:39+00:00`（UTC），采集窗口约 40–50 分钟，个别补充项目在窗口内稍晚采集（`source` 与 `data/raw/*.json` 内 `_snapshot_utc` 记录）。
- **接口**：GitHub REST API（`api.github.com`）
  - `/repos/{owner}/{repo}`（主端点，49 个）
  - `/search/repositories`（因核心 API 60 次/小时配额耗尽后改用，11 个，已在台账 `source` 列注明）
  - `/search/repositories` topic/关键词检索 5 组（结果存 `data/search/`）
- **字段**：stars、forks、watchers(subscribers)、open_issues、language、license、created_at、pushed_at、archived、topics、description、html_url。
- **留痕**：每个项目完整响应 JSON 存 `data/raw/`；采集脚本存 `process/collect_github_data.py`；台账 `data/ledger.csv`。

## 五、多源核验方法

| 层 | 来源 | 覆盖 |
|---|---|---|
| 第一源 | GitHub `/repos` 端点（采集主值） | 49 个 |
| 第二源 | GitHub `/search/repositories` 端点（复核） | 23 个双端点交叉 |
| 第三源 | ai-agent-pulse（同日）、Agent-Leaderboard（2026-08-04）、公开报道（多日期） | 头部/框架类 |
判定规则：第二源与主值差异 ≤1（实时 star 波动）即通过；第三方仅做量级与趋势一致性判断（其自身有更新滞后，明确标注）。

## 六、分析方法

- **分类**：以「交付形态 × 使用对象」为第一性原则，分 7 类；交叉项目按首要定位归类并在文中标注。
- **维度对比**：定位/心智模型、主要语言、许可证、规模、活跃度、生态背书、适用场景、上手难度、多智能体能力、MCP 支持。
- **洞察原则**：每条结论可回溯到台账/核验记录中的数字；无法用本次数据证明的判断明确标注为「定性判断」。

## 八、局限与方法学声明

- 单时点快照；star 每分钟实时波动（核验中实测 ±1）。
- 部分项目因配额改由 search API 采集（GitHub 官方同源，已在台账标注，不影响真实性）。
- 「活跃度」以最近推送日期为代理，未含提交频率/PR/Issue 全貌（补充了 ai-agent-pulse 的 4 周提交与 7 日增速作第三方交叉）。
- 分类按首要定位，存在天然交叉（如 LangGraph 亦常用于多智能体）。
- 未评估代码质量、文档、安全与生产可用性；star 多 ≠ 工程成熟。
- 第三方榜单存在更新滞后，仅作方向性核验。
- AI agent 领域变化极快，本报告结论具有时效性（数据时点 2026-08-11）。
