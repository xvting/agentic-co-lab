## 执行摘要

1. **生态主导权已交接**：2026 年 8 月的热度榜头部分别是 2025–2026 年创建的**成品 Agent 与技能层**项目——`openclaw/openclaw`（385,885★，全 GitHub 软件项目第一）、`obra/superpowers`（270,517★）、`affaan-m/ECC`（239,335★）、`NousResearch/hermes-agent`（228,737★）；而 2023 年的先驱（AutoGPT、MetaGPT、AutoGen、Swarm）star 存量仍高，但**活跃度明显下滑或进入维护模式**（MetaGPT 202 天、AutoGen/Swarm 118 天未推送；AutoGen 10 个月未发版、4 周 0 提交）。
2. **三大模型厂商的终端 CLI 正面交锋**：Claude Code（141,016★）、Codex（105,274★）、Gemini CLI（106,457★）均为 2025 年发布、约一年半内冲上 10 万+；开源编码 agent 矩阵（OpenHands、OpenCode、Cline、Aider、Goose、Continue、pi）同步繁荣。
3. **新品类爆发：Agent 技能/增强层**。以 CLAUDE.md/skills/插件为分发单元的技能框架（superpowers、ECC、hermes-agent、claude-mem）增速超过多数传统框架——用户痛点正从「学新框架」转向「让现有 agent 更好用」。
4. **多智能体编排进入洗牌期**：AutoGen 官方迁移至 Microsoft Agent Framework/AG2；CrewAI（角色化，7 日 +328★）与 LangGraph（图+持久化，7 日 +589★）成为两条主流路线；deer-flow（79,727★）代表「长程任务 SuperAgent」新方向。
5. **基础设施协议化**：MCP 成为事实标准（官方实现 89,427★，社区榜单 9.2 万★），A2A（25,284★）指向 agent↔agent 互操作；记忆（mem0/Letta/claude-mem）、工具（Composio）、数据（Firecrawl/RAGFlow）各自成赛道。
6. **选型警示**：star 是「历史品牌 + 当下热度」的混合信号，与工程活跃度可能背离（AutoGPT、MetaGPT、AutoGen 即例证）。本报告同时给出 star、活跃度、第三方动量三层证据。

## 一、调研范围与方法（摘要）

- **样本**：60 个代表性项目，选取流程 = 领域预选（42）→ GitHub search API 客观检索补漏（topic:ai-agents 等 5 组 Top30）→ 第三方榜单交叉（ai-agent-pulse 19 框架、Agent-Leaderboard 5 板块）→ 增补与更正（含 openclaw、opencode 继任等）。
- **度量**：star 数（规模/热度）、forks/watchers（社区参与）、最近推送日期（活跃度代理）、创建日期（代际）、许可证（合规前提）；第三方 7 日 star 增量与 4 周提交（动量）。
- **核验**：23 个项目双端点交叉（差异 ≤1）；ai-agent-pulse（同日）19 框架量级全部一致；公开报道趋势一致。详见《数据核验记录》。
- **诚实边界**：单时点快照；star 每分钟波动 ±1；部分项目因配额由 search API 采集（同源官方，已标注）；「活跃度」以最近推送为代理；分类按首要定位存在交叉；未评估代码质量/安全。

## 四、分领域分析

### 4.1 框架与开发库（18 个）——「图编排 vs 轻量 vs 结构化」三分

- **生产级图编排**：LangGraph 以「图 + 持久化 + 人机协同」成为生产标杆（Pulse 75.3，7 日 +589★）；LangChain 作为其父生态（143,963★）仍是最大入口。
- **官方轻量 SDK**：OpenAI Agents SDK（28,555★，handoffs）、Google ADK（21,069★）、Claude Agent SDK（1,688★，SDK 本体小但 CLI 141k）——模型厂商通过 SDK 锁定开发者心智。
- **结构化/极简**：PydanticAI（19,219★）以类型安全为卖点；Smolagents（28,751★）极简 code-agent（但 2 个月未发版、4 周 0 提交，Pulse 37.7 偏低）；Semantic Kernel（28,439★）服务企业现有技术栈（C#/Java）。
- **TS 全栈**：Mastra（27,097★，4 周 1292 提交，开发最活跃）、Vercel AI SDK（26,125★）服务前端/全栈场景；Microsoft Agent Framework（12,727★）是 AutoGen 的官方继任。
- **洞察**：框架层没有统一赢家——「状态与生产」「类型安全」「极简」「厂商绑定」「前端接入」各占位；选型取决于**已有技术栈 + 是否需要持久化状态**。

### 4.3 编码与通用 Agent 应用（15+2 个）——终端入口争夺战

- **官方 CLI 三巨头**（均为 2025 年发布、约一年半内 10 万+）：Claude Code 141,016 / Gemini CLI 106,457 / Codex 105,274——终端成为模型厂商的直接入口。
- **开源编码矩阵**：OpenCode（继任仓库 `anomalyco/opencode`，196,028★，TypeScript）、OpenHands（83,691★，自主工程平台）、pi（87,258★）、Cline（65,991★，IDE 插件）、Goose（52,669★，Rust）、Aider（48,116★，git 原生，81 天未推送）、Continue（35,430★，IDE）、Skyvern（22,730★，网页自动化）、browser-use（108,742★，浏览器库，7 日 +904★，Pulse 89.2 全场第一）。
- **个人助理/研究**：OpenClaw（385,885★，2025-11 创建，全平台个人 AI 助理，登顶 GitHub 总榜）；autoresearch（93,644★，Karpathy 的实验性研究 agent，138 天未推送，属实验项目）。
- **洞察**：编码 agent 是当前最成熟、竞争最激烈的赛道；「官方 CLI + 开源替代 + 浏览器自动化」构成三层，其中**浏览器自动化（browser-use）是当前动量最高的细分**。

### 4.4 平台/低代码（6 个）——业务侧需求旺盛

- n8n（200,194★，含 agent 节点与 MCP，工作流自动化老牌平台）、Langflow（153,046★，可视化 agent 构建）、Dify（152,076★，LLM 应用平台，自 2026-01 破 10 万后高速增长）、Open WebUI（148,456★，自托管门户）、LobeHub（81,492★）、Flowise（55,316★）。
- **洞察**：平台层与框架层互补而非替代——**业务用户用平台（低代码），开发者用框架（代码）**；六家平台 star 合计约 79 万，证明「无代码搭 agent」是真实刚需。

### 4.5 协议/基础设施/记忆（9 个）——生态的「水电煤」

- **协议**：MCP（spec 8,921 + servers 89,427★）已成为 agent 工具连接的事实标准（社区 awesome-mcp-servers 9.2 万★、chrome-devtools-mcp 4.9 万★、github-mcp-server 3 万★为佐证）；A2A（25,284★，Google 主导）指向 agent↔agent 互操作。
- **记忆**：mem0（63,014★）、claude-mem（90,376★，技能型记忆）、Letta（24,186★）。
- **工具/数据**：Composio（29,627★，1000+ 工具与远程 MCP 服务器）、Firecrawl（165,519★，网页上下文 API）、RAGFlow（87,248★，RAG 引擎）。
- **洞察**：agent 数量爆发后，瓶颈从「能不能生成」转向「连得上工具、记得住上下文、拿得到数据」——基础设施层是 2026 年确定性最强的增长方向。

### 4.6 Agent 技能/增强层（新品类，2025-10 后爆发）

- superpowers（270,517★，2025-10 创建）：Agentic Skills 框架 + 开发方法论，以「技能包」形式注入编码 agent；
- ECC（239,335★，2026-01 创建）：Agent harness 性能优化（skills/instincts/memory），目标是让 Claude Code/Codex 更快、更省 token；
- hermes-agent（228,737★，2025-07 创建）：「成长型 agent」，技能随使用增长；
- claude-mem（90,376★）：跨会话持久记忆。
- **洞察**：这类项目不替代框架，而是**增强现有 agent**——其 star 在发布后约 9–13 个月内冲到 20–38 万，增速远超多数框架，标志 2026 年的核心矛盾是「现有 agent 不够好用」而非「没有新框架」。

## 六、洞察与结论（数据驱动）

1. **时代切换：从「框架」到「成品 Agent + 技能层」**。Top10 中 4 个为 2024-10 后创建，且前 4 名全部来自 2025–2026；2023 先驱（AutoGPT/MetaGPT/AutoGen）活跃度全面回落（MetaGPT 202 天、AutoGen 118 天）。**star 存量是历史品牌，活跃度才是当下动能。**
2. **模型厂商的「入口战争」集中在终端 CLI**：Anthropic/OpenAI/Google 三家官方 CLI 约一年半内全部破 10 万★。终端是比 IDE 更轻、更可控的 agent 入口；开源替代（OpenCode 196k/OpenHands 84k）以「可自托管、模型无关」差异化。
3. **技能/增强层是 2026 年最大新品类**：superpowers/ECC/hermes-agent 合计约 74 万★，均诞生于最近一年内。分发单元从「框架」变成「可移植技能包」，跨 Claude Code/Codex/Gemini CLI/Cursor 复用。
4. **多智能体从演示走向生产，胜者是「可控」**：CrewAI（角色化，+328/7d）、LangGraph（图+持久化，+589/7d）、deer-flow（长程 harness，79.7k★）获得动能；Swarm 停滞、AutoGen 维护模式。**「多」不是卖点，「可恢复、可观测、可编排」才是。**
5. **MCP 完成事实标准化，A2A 开辟第二协议**：MCP 生态（官方实现 + 社区榜单 9 万+）已渗透到平台（n8n/dify/Open WebUI）、框架（AgentScope/Mastra/Haystack）与工具层（Composio）。跨厂商 agent 互操作（A2A）是下一个待垦地。
6. **Python 主导开发层、TypeScript 崛起于应用/平台层**：31/60 为 Python；但 OpenClaw、n8n、Dify、Open WebUI、LobeHub、Mastra、Composio、Firecrawl 等头部应用/平台均为 TS。
7. **中文/中国团队深度参与**：deer-flow（字节）、AgentScope（阿里）、RAGFlow、MetaGPT 及大量中文技能/教程/榜单仓库——本生态已高度全球化，中文本地化内容供给活跃。
8. **选型三问**：① 看活跃度与发版（而非只看 star，AutoGPT/MetaGPT/AutoGen 为反例）；② 核对许可证（60 个样本中 14 个为非标准/无许可证）；③ 明确「代码 vs 低代码」「框架 vs 成品」「单机 vs 托管」三条轴后再选。

## 七、风险与局限（诚实标注）

1. **单时点快照**：数据为 2026-08-11T10:22:39Z 前后约 40–50 分钟内采集；star 每分钟波动 ±1（双端点复核实测）。
2. **配额降级**：11 个补充项目因核心 API 60 次/小时配额限制改用 search API（GitHub 官方同源），台账 `source` 列逐一标注；不影响真实性，但严格意义上部分项目未走主端点。
3. **活跃度代理**：「最近推送」不反映提交频率/PR/Issue 全貌；已用 ai-agent-pulse 的 4 周提交与 7 日增量交叉，但该第三方自身为自动化快照，可能有数小时到数天滞后。
4. **star ≠ 质量**：未评估代码质量、文档、安全、生产可用性；部分头部项目（如 OpenClaw 38.6 万★）创建不足 1 年，成熟度待观察；公开报道亦提示个人 Agent 存在安全风险。
5. **分类主观性**：按「交付形态 × 使用对象」分类存在天然交叉（LangGraph 等），已提供台账全量分组供读者重排。
6. **未覆盖项**：非开源/闭源产品（Devin、Manus、Cursor、Coze 等）与纯列表/教程类仓库未入主样本（见「附：生态邻接」）；star-history.com 因 GitHub 限制不可用，未获得逐日增长曲线。
7. **时效性**：AI agent 领域变化以周计；本报告结论截至数据时点，头部格局可能快速变化（如 openclaw 2025-11 创建后 9 个月登顶即是例证）。
