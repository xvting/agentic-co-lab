# 如何验证智能体协作效果

> 方法论文档 · 基于 Agentic Co-Lab EXP-001~009 真实实验证据（n=1~3，探索性）
> 版本 v1.0 · 2026-08-11 · 对外可引用/分享 · 中文
> 证据来源：`company/projects/experiments/`（EXP-001~009 报告）、`benchmark/README.md`、`company/operations-manual.md`（R2/R3/R4）

## 一、核心思路：用对照实验回答"协作有没有用"

"多智能体协作是否有效"不能靠感觉回答，应改写为**可证伪的对照问题**：同一标准任务下，协作组是否在客观/盲评指标上显著优于单人直出，且增益值得额外成本？

- 自变量：组设计（单人 vs 多角色协作）
- 因变量：产出质量（客观通过率 / 盲评分数）
- 成本变量：代理数 × 轮次
- 判据：质量增益 vs 成本倍数（我们的实测中，增益仅出现在开放任务，且常伴随 4 倍成本）

## 二、五个关键设计要素

1. **标准任务**：用 benchmark 统一任务描述与评测方式，跨实验、跨团队可对比。
2. **对照组**：必须有"单人直出"基线臂；只有协作臂、没有基线，不构成证据。
3. **客观评测优先**：编码/数据处理用测试套件（`RESULT n/m`）；主观任务用统一 rubric 量表（5 维 × 1-5）。能客观就不主观。
4. **盲评**：产出匿名编号、评审与撰写分离；确需自评必须声明（EXP-001 的教训：评审者已知归属，存在偏好偏差）。
5. **证据标注**：每个结论注明 n、任务类型、评测方式与口径（R3 诚实汇报）；"无显著差异"也是有效结论。

## 三、标准实验流程（8 步）

1. **选任务**：从 `benchmark/tasks/` 选标准任务（当前 6 个）。
2. **定组设计**：单人臂 + 协作臂；角色数默认 3；明确处理路径（独立生成→择优，或融合）。
3. **写协议**：编号/日期/任务/组设计/评测方式（R2：协议先行、可追溯）。
4. **执行**：各代理独立产出、互不沟通、落盘存档并匿名编号。
5. **评测**：客观跑套件；主观按 `tasks/rubric.md` 盲评（评审 ≠ 撰写）。
6. **记成本**：代理数 × 轮次，算性价比（质量分 ÷ 成本单位）。
7. **写报告**：按 benchmark 模板记录产出原文、评测、成本、结论与局限。
8. **沉淀**：结论回填 README 基准线，必要时更新运营手册。

## 四、两个真实例子（正反对照）

**正例 · EXP-001 开放文案（定位声明）**
单人稿 **16 分**；3 角色协作 → 融合稿 **19 分（+19%）**；成本 1 → 4 成本单位。机制：研究/工程/产品三视角互补，整合稿在清晰度与可执行性上明显更优。局限：n=1、单任务、盲评不严格（评审已知各稿归属）。

**反例 · EXP-002 确定性编码（括号算法）**
15 个用例客观评测：单人 **15/15 = 协作 15/15**（四稿全部满分，质量 5/5/5），增益 **+0%**；成本同样 4 倍。机制：教科书级任务单轮直出即最优，多角色是重复劳动。

→ 对照结论：**协作价值 ∝ 任务开放性 × 复杂度**。确定性任务协作纯属浪费，开放多维任务协作有真实增益。

## 五、已验证结论 vs 未验证局限

**已验证（证据 EXP-001~009，n=1~3 探索性）**
1. 确定性/接口明确型编码任务协作 +0%（EXP-002、EXP-008：30/30×3）。
2. 分析推理任务单轮直出即根因趋同，择优稿=最高单稿，+0%（EXP-009：23/23/25 → 25/25）。
3. 开放多维任务存在协作增益（EXP-001：+19%），但样本极小。
4. 3 角色为择优甜点（EXP-005：23/25 饱和，5/7 无增量）；择优性价比高于融合（EXP-004，R1a）。
5. R4 独立评审是当前最稳定的正向增量（EXP-006/007：择优稿 22 → 评审修订 24，约 +9%，成本仅 +1 评审代理）。

**未验证局限（诚实边界）**
- 全部实验 n=1~3、单评审、探索性，不具统计意义，不可外推。
- 盲评/自评偏差未消除（EXP-001 已知归属；EXP-007 采纳稿由 CEO 自评）。
- 上限/天花板效应（30/30、25/25）掩盖更细粒度差异（EXP-008/009）。
- 协作增益临界点未定位：小型 API 设计等"行为规范开放"任务尚未测试。
- 单代理栈、单轮；模型/协议更新后结论可能变化。

## 六、如何复现：用 benchmark 套件跑自己的对照实验

1. **编码任务（客观）**：`python tasks/test_suite_brackets.py <你的解文件>`（另有 ttlcache、log_analyzer 套件），输出 `RESULT n/m`。
2. **文案/战略/分析任务（主观）**：用 `benchmark/tasks/task-*.md` 的描述让单人/协作组各自产出 → 按 `tasks/rubric.md`（权威量表，非脚手架模板）盲评 → 记录成本。
3. 按报告模板提交，与 README 的 EXP-001~009 基准线对照。
4. 复现时**不改任务、不改量表**，只改组设计；否则结果不可比。

## 七、与其他机制的衔接

- **R4 独立评审**：正式输出（定位/OKR）必经独立评审；"择优 → 评审 → 修订"再 +9%（EXP-007），建议纳入标准环节。
- **角色数甜点**：默认 3 角色；更多角色只补维度覆盖、不补质量上限（EXP-005）。
- **择优 > 融合**：默认独立生成→择优（性价比最高）；融合仅用于合并多方实质要素（R1a）；融合稿自评存在虚高风险，须经独立评审（EXP-004）。
- **路由规则（R1）**：确定性/规范明确 → 单人直出；开放高复杂 → 3 角色协作 + R4。
