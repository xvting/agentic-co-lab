# 智能体公司搭建实操指南 v1.1

> 基于 Agentic Co-Lab 五轮真实对照实验（EXP-001~005）沉淀。
> 三视角独立撰写后择优融合，经独立评审（R4）修订。
> 变更：v1.0 → v1.1（修复自查表矛盾、补证据附录、附角色卡模板与评测 SOP）。

## 一、概述
智能体公司 = 一群带专业角色的 AI 智能体，按既定流程协作完成任务的可编程组织：**把"如何配合"标准化，而非堆模型**。

## 二、起步清单（5 步，附完成标志）
| # | 步骤 | 完成标志 |
|---|---|---|
| 1 | 定义 3 个角色（研究员/CTO/PM），各写一张角色卡 | 每卡含身份/专业/职责/原则/验收标准（模板见附录 B） |
| 2 | 搭最小闭环：任务 → 多角色独立产出 → 统一评测 → 沉淀结论 | 跑通 1 次完整闭环 |
| 3 | 立章程与 OKR，固定周会评审；明确主代理派单与评审 | 章程/OKR 落档 + 1 次周会纪要 |
| 4 | 建测试套件与评测量表（客观用例 + 主观量表 + 盲评） | 套件可运行，量表锚点明确（SOP 见附录 B） |
| 5 | 跑第一个开放、面向真实用户的小项目 | 产出物 + 协议/报告成对存档 |

## 三、三条核心方法（实证）
1. **任务分级路由**：确定性/低复杂度 → 单人直出（协作 +0%，EXP-002）；中等 → 默认单人、高价值才协作（+7%，EXP-003）；开放/高价值 → 3 角色协作（+19%，EXP-001）。（基线见附录 A）
2. **3 角色是甜点值**：择优上限 3 角色即饱和；扩到 5/7 只补维度覆盖、成本翻倍（EXP-005）。
3. **择优 > 融合**：多稿独立生成后直接挑最优，性价比最高；融合仅用于合并实质要素（如全维度 OKR，属例外场景——此时扩员的价值是覆盖多维度，而非提升质量上限，与第 2 条不矛盾）。警惕自评虚高（EXP-004）。

## 四、工程落地要点
- **角色卡 = 结构化提示词**：身份/专业/职责/原则写满；确定性任务角色趋同，开放任务才显差异。
- **编排**：LangGraph 管流程状态与分支，AutoGen 管对话协作；先线性后并行，别一上来就复杂图。
- **评测**：客观任务用测试套件算通过率；主观任务用量表 + 锚点 + 盲评（执行者与撰写者分离），记录成本。
- **先实验后基建**：小样本验证再投钱，不建无用基建。

## 五、常见坑（对照自查）
1. **事事拉协作**：确定性任务花 4 倍成本换 0 增益。
2. **角色越多越好**：择优场景 3 个就够。
3. **强制融合草稿**：可能拉低最优稿，默认择优。
4. **自评当定稿**：正式输出须独立评审（R4），防虚高。
5. **无证据的数字**：引用增益/成本时附基线、样本量与评测口径（见附录 A）。

## 六、快速自查表
| 你面对的任务 | 动作 |
|---|---|
| 改一行配置 / 已知算法 | 单人直出 |
| 设计模块 / API | 单人；重要则 3 角色 |
| 制定战略 / 定位 / 愿景 | 3 角色独立生成 → 择优 |
| 定全公司 OKR | 3 角色融合；需全维度可扩 5-7（例外） |
| 多稿在手，如何定稿 | 先择优；仅实质要素互补才融合 |
| 正式输出前 | 过一遍 R4 独立评审 |

## 附录 B · 角色卡模板 + 评测 SOP
**角色卡模板**（复制即用）：
```
# 角色卡 · {{代号}}
## 身份：代号/部门/汇报对象
## 培训背景：专业领域 ×2、关注方向、行为准则
## 职责：3 条
## 工作原则：先结论后论据 / 建议含"做什么-为什么-风险-验证" / 主动指出盲区
```

**评测 SOP**：
1. 客观任务：独立 test_suite.py 导入解文件，循环用例输出 `RESULT n/m`。
2. 主观任务：固定量表（清晰度/差异化/可执行性/感染力/完成度，各 1-5）+ 锚点描述。
3. 盲评：草稿匿名编号；评审者与撰写者分离；若自评须声明。
4. 记录成本：代理数 × 轮次（token 可得时另记）。
