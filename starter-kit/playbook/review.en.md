# Review & Persistence Playbook (R2~R5)

> Based on EXP-001~005. Answers: how to guarantee quality? how to persist assets?

## R2 · Experiment first
- Validate on a small sample before scaling; **never build unneeded infrastructure**.
- Every experiment persists: protocol + report + raw outputs.

## R3 · Honest reporting
- Label evidence strength: n, task type, evaluation method.
- "No significant difference" is a valid conclusion (EXP-002's 0% is just as valuable).

## R4 · Independent review
- Formal outputs (positioning / vision / OKR / code release) require independent review.
- Declare reviewer-author relationship; integrator self-review inflates (EXP-004).

## R5 · Knowledge persistence
- Every decision lands in a formal document, traceable to evidence.
- Recommended layout: see operations-manual.en.md R5.
