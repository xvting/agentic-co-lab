# 评审与沉淀机制（运营手册 R2~R5）

> 依据 EXP-001~005 实证。解决两个问题：怎么保证质量？怎么沉淀资产？

## R2 · 实验先行
- 重大决策先小样本验证，再规模化；**不建无用基建**（EXP-001 教训：先跑实验再买工具）。
- 每个实验必存：协议 + 报告 + 原始产出。

## R3 · 诚实汇报
- 结论标注证据强度：n 值、任务类型、评测方式。
- "无显著差异"也是有效结论，不粉饰（EXP-002 的 0% 同样值钱）。

## R4 · 独立评审
- 正式输出（定位/愿景/OKR/代码上线）须经独立评审。
- 采纳前声明评审者与撰写者关系；整合者自评有虚高风险（EXP-004 教训）。

## R5 · 知识沉淀
- 每轮决策落地为正式文档，与实验证据一一对应。
- 推荐目录：
```
org/
├── charter.md            # 章程
├── statements/           # 定位/愿景
├── okr.md                # 目标
├── operations-manual.md  # 运营手册（本册）
├── agents/               # 角色卡
├── meetings/             # 纪要
└── projects/experiments/ # 实验证据链
```
