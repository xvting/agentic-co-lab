# Task Routing Playbook (R1 + R1a)

> Based on EXP-001~005. Core question: how many people, and how, for this task?

## R1 · Choose mode by complexity

| Task characteristics | Mode | Roles | Why |
|---|---|---|---|
| Low / deterministic | Solo | 1 | Collab gain 0% (EXP-002) |
| Medium / function+design | Solo by default; collaborate for high value | 3 | Collab +7%, depends (EXP-003) |
| High / open / cross-disciplinary | Multi-role collaboration | **3** | Collab +19% (EXP-001) |

## R1a · Handling multiple drafts

Once you have N independent drafts:
1. **Default select-best**: pick the best draft. Best cost-effectiveness (EXP-004).
2. **Merge only when needed**: when combining substantive elements (e.g., company-wide OKR). Declare integrator self-review bias.
3. **Don't over-staff**: quality saturates at 3 roles; more roles add coverage only (EXP-005).

## Quick decision table
| Task you face | Action |
|---|---|
| Change a config line | Solo |
| Implement a known algorithm | Solo |
| Design a module / API | Solo; 3 roles if high-value |
| Strategy / positioning / vision | 3 roles, independent → select-best |
| Company-wide OKR | 3~7 roles → merge (adds coverage) |
