# 任务分级路由（运营手册 R1 + R1a）

> 依据 EXP-001~005 实证。核心问题：这个任务该几个人、怎么干？

## R1 · 按复杂度选模式

| 任务特征 | 模式 | 角色数 | 理由 |
|---|---|---|---|
| 低复杂度 / 确定性 | 单人直出 | 1 | 协作增益 0%（EXP-002） |
| 中复杂度 / 功能+设计 | 默认单人；高价值才协作 | 3 | 协作 +7%，看重要性（EXP-003） |
| 高复杂度 / 开放 / 跨学科 | 多角色协作 | **3** | 协作 +19%（EXP-001） |

## R1a · 多稿怎么处理

拿到 N 份独立草稿后：
1. **默认择优**：直接挑最优稿。性价比最高（EXP-004）。
2. **特殊才融合**：需要合并多方实质要素时（如全维度 OKR）再融合，并标注整合者自评偏差。
3. **别扩编**：3 角色后质量上限不再涨，扩员只补维度覆盖（EXP-005）。

## 快速判断表
| 你面对的任务 | 动作 |
|---|---|
| 改一行配置 | 单人直出 |
| 写一个已知算法 | 单人直出 |
| 设计一个模块/API | 单人；重要则 3 角色 |
| 制定战略/定位/愿景 | 3 角色独立生成 → 择优 |
| 定全公司 OKR | 3~7 角色 → 融合（补维度） |
